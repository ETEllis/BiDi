# Origin and evolution

BiDi grew through a reciprocal exchange between Edward Ellis's theories,
products, formal work, and executable systems. A theory would reach the point
where intuition needed a language. A product would expose behavior that needed
a reproducible state contract. An implementation would reveal that a concept
was too loose to execute or test. Each gap became material for the next pass.

That is why BiDi now spans more than one conventional software category. The
calculus, native runtime, guarded operators, recurrence analysis, receipts,
formal mirrors, research lanes, and instruments are accumulated answers to the
same recurring problem: how can a transformation remain coherent as it moves
from an idea into an executable event and then back into theory or product as
usable evidence?

## The feedback loop

The build process is intentionally reciprocal:

```text
theory or product demand
  -> missing formalism, state, behavior, or evidence becomes visible
  -> CDC expresses the contract
  -> the native runtime executes the path
  -> U1/U2 and verification gates test what the path earned
  -> receipts, proofs, and instruments expose the result
  -> the result sharpens the originating theory or product
  -> the next demand enters with greater precision
```

Theories and products pressure-test the operator system. The operator system
returns stronger mechanisms, clearer state boundaries, executable alternatives,
and falsifiable questions. BiDi is the shared substrate produced by that loop.

## June 2026: from conceptual calculus to native mechanism

The first repository pass established the Coherence-Delta Calculus as a compact
language for hybrid state evolution. Balanced-ternary commitment, synchronous
flow, and nested cross-scale exchange gave recurring ideas about coherence,
opposition, aperture, and multi-level interaction an explicit operational form.

The next passes immediately tested whether that form could survive execution.
The invariant registry, angular-path relations, ternary trace windows, bridge
codebooks, native reducer, replay surface, and finite Lean/Rocq mirrors turned
the calculus from an explanatory vocabulary into working machinery.

## July 2026: tasks, the Universal Operator, and embodied instruments

Transition, procedural, episodic, and deliberative frameworks pushed CDC into
complete task behavior. Their composition exposed the need for an operator that
could preserve local decisions, reciprocal roles, topology, record agreement,
and enacted effects across one path. That pressure produced the guarded
Universal Operator layer now called U1.

The Möbius work then fed the abstraction from the product side. Its connected
body, one-turn/two-turn cover behavior, orientation, aperture, and identity
motion made relationships visible that the formal system needed to distinguish
precisely. In return, the operator hierarchy gave the product an executable
state language, receipt vocabulary, and a canonical `𝒰_` identity tied to
behavior rather than decoration.

Repository landmarks: `5d5f2b9`, `e128e8f`, `fc062ae`, `82f27e0`, `313f0a1`.

## July 2026: one source-to-evidence path

As the system began serving wider product and research work, the separation
between declaration, runtime, persistence, verification, and presentation
became a practical engineering problem. The native toolchain, shared parser,
stable ABI, fused executor, durable store, typed receipts, provenance manifest,
reproducible builds, CDC Studio, and web evidence console were built to keep
those surfaces on the same source-bound path.

Connections to the Memory Manifold, Superposition, and reference-frame work
made that path reusable beyond one repository concern. Those lanes contributed
demands for durable identity, replay, authority, causal ordering, recursive
cells, and cross-boundary reconciliation. BiDi returned explicit interfaces and
executable contracts that those larger systems could consume and challenge.

## August 2026: variation, return, and the whole system

The next theoretical question was no longer whether an accepted path could run,
but what changed along it and whether it truly returned. U2 answered that
pressure with source-bound differentiation, complete state manifests,
recurrence gates, explicit relative restoration, validated real-Schur analysis,
and typed spectral holds. The canonical loop could now earn its tangent while
honestly holding recurrence, and a bounded restored fixture could earn its
return operator and marginal spectrum.

That result clarified the repository's highest-level identity. CDC remained the
formal language and native kernel, while BiDi became the proper name for the
whole Universal Operator System: source, runtime, U1, U2, receipts, formal
mirrors, instruments, paper, and research interfaces operating as one
inspectable architecture.

Repository landmarks: `c0f991b`, `d917c06`, `7f7796a`, `71ed346`.

## Human-agent method

Edward Ellis leads the conceptual program and product direction. Agent systems
serve as research, formalization, implementation, synthesis, and adversarial
review instruments. Ideas move through parallel exploration, but they enter the
system only by becoming inspectable source, executable behavior, permanent
counterexamples, reproducible receipts, or precisely scoped formal statements.

This method is itself part of BiDi's evolution. Human intuition can range across
theories and products at full amplitude; agent work can fan out across
implementation and verification; the repository then provides the shared
object against which both are corrected. The result is a collaboration that
compounds without asking memory, prose, or confidence to substitute for the
artifact.

## The continuing program

BiDi is designed to keep receiving pressure from the work around it. A new
theory can contribute an operator, state map, symmetry, or falsifier. A product
can contribute a behavior, interaction, or evidence requirement. A runtime can
expose a missing semantic distinction. A proof or experiment can force a
revision. Each successful pass returns to the wider body of work as reusable
formal and executable machinery.

That continuing loop is the system's real history and its route forward.
